## B. Reddit-пост (r/FlutterDev и r/Dart; кросспост предупредить модов)

**Заголовок:**

```
I built a YouTube extraction library in pure Dart — on-device player.js execution and BotGuard PO tokens, no server (alternative to NewPipeExtractor for Flutter apps)
```

**Текст:**

```
Hey everyone,

The problem: if you want YouTube data inside a Flutter/Dart app, the
options are all heavyweight — NewPipeExtractor means shipping a JVM
runtime, yt-dlp means a Python runtime or your own server. There was
no production-tested way to do it in-process in Dart.

So I built KMEP: https://github.com/dipodev20/kmep

What it does:

- Video metadata + resolved stream URLs, up to 4K, live/HLS support
- Multi-client InnerTube fallback (ANDROID_VR → WEB → IOS → WEB_SAFARI → TV) —
  the order is tunable at runtime via remote config, so when YouTube
  breaks a client overnight, you fix it without an app release
- Real player.js execution for signature/n resolution (QuickJS kept
  crashing on it, so it runs in a headless WebView on mobile / Node on
  servers — you provide the JS runtime via a small interface)
- On-device BotGuard PO token generation — this is the part I'm
  proudest of: no bgutil server, no external attestation service.
  The token is generated by the same BotGuard program YouTube's own
  web client runs, executed on the device
- Typed API for search, shorts, channels, playlists and comments

Production track record: it's been the default engine of my daily-driver
Android app for over a month — 98% success rate (49/50 live-audited),
and the router falls back to NewPipeExtractor on the rare miss so users
never hit a dead end.

Honest limitations (also in the README): IP reputation is the ceiling
for every extractor including this one; YouTube changes things every few
weeks (though that's usually a config fix here, not a release); and
it's pre-1.0 GPLv3.

Question for the community: what would you want from a YouTube
extraction library before you'd depend on it — pub.dev publishing?
Multi-platform JS runtimes? A 1.0 stability commitment? Genuinely
curious what gates adoption for you.

https://github.com/dipodev20/kmep
```

## C. Habr-статья (лонгрид, на русском)

**Заголовок:**

```
Как я написал YouTube-экстрактор на Dart с on-device BotGuard: разбор архитектуры KMEP
```

**Черновик статьи (Hubr-разметка):**

```markdown
## Проблема

Ecть NewPipeExtractor (JVM), yt-dlp (Python) и… всё. Если вы пишете
приложение на Flutter/Dart и хотите доставать данные с YouTube без
официального API, вы либо тащите JVM-рантайм в otherwise-чистое
приложение, либо строите сервер вокруг yt-dlp. Оба варианта — по
80+ МБ зависимостей и процессов, которые надо удерживать живыми.

KMEP (https://github.com/dipodev20/kmep) решает это иначе: весь
пайплайн экстракции — внутри процесса вашего Dart/Flutter-приложения.

## Решение

KMEP говорит с теми же InnerTube-эндпоинтами, что и официальные
приложения YouTube. Три инженерных проблемы, из которых состоит
экстракция, и как каждая решена:

**1. Получение URL стримов.** YouTube отдаёт разные данные разным
«клиентам», и они ломаются независимо друг от друга. KMEP
перебирает пять — ANDROID_VR (keyless, прямые URL, player.js не
нужен), затем WEB, IOS, WEB_SAFARI, TV — и порядок задаётся
конфигом, который приложение может подтянуть по воздуху.

**2. Подписи.** Браузерные клиенты отдают URL с отравленным
n-параметром: без разворота видео режется до ~70 Кбит/с. Надёжный
способ разворота один — исполнить сам player.js. KMEP гоняет его
в реальном JS-движке (headless WebView на мобильных, Node на
сервере). QuickJS пробовали первым — падает недетерминированно.

**3. PO-токены.** Часть клиентов теперь требует BotGuard-аттестацию.
Стандартное решение — отдельный bgutil-сервер. KMEP генерирует
токен на устройстве: та же BotGuard-программа, что исполняет
веб-клиент YouTube, — в вашем JS-рантайме, без сервера.

## Примеры

```dart
final kmep = Kmep.withOnDevicePoToken(
  jsRuntime: WebViewJsRuntime(),
  potJsRuntime: WebViewJsRuntime(), // отдельный JS-контекст!
  fetchText: (url) => http.get(Uri.parse(url)).then((r) => r.body),
);

final video    = await kmep.getVideo('dQw4w9WgXcQ'); // 27 стримов
final results  = await kmep.search('lofi hip hop');
final channel  = await kmep.getChannel('UC-lHJZR3Gqxm24_Vd_AJ5Yw');
final playlist = await kmep.getPlaylist('PLFgquLnL59alCl_2TQvOiD5Vgm1hCaGSI');
final comments = await kmep.getComments('dQw4w9WgXcQ');
```

Поиск, каналы, плейлисты и комментарии идут через
неаутентифицированный WEB-клиент — без player.js и PO-токенов,
работают даже в CLI-скриптах.

## Сравнение

| | KMEP | NewPipeExtractor | yt-dlp | NewPipe/LibreTube/FreeTube |
|---|---|---|---|---|
| Что это | Dart-библиотека | JVM-библиотека | Python CLI | Готовые приложения |
| Внутри Flutter-приложения | нативно, одна зависимость | через JVM/мосты | через сервер/Python | — |
| PO-токены | на устройстве, встроено | нет | внешний bgutil-сервер | по-разному |
| Фолбэк при поломках YouTube | 5 клиентов + runtime-конфиг | фиксы релизами | фиксы релизами | фиксы релизами |
| API поиска/каналов/комментариев | типизированный Dart | экстракторы JVM | CLI/JSON | UI приложения |
| Лицензия | GPLv3 | GPLv3 | Unlicense | разные (в осн. GPL) |

Честная таблица означает: на JVM берите NewPipeExtractor, на сервере
yt-dlp непобедим. Ниша KMEP — Flutter/Dart-приложения, которым нужен
движок внутри процесса.

## Цифры

- 98% успеха (49/50) на живой выборке, методология — в
  docs/AGENT_HANDOFF.md
- Месяц в проде ежедневного Android-приложения, 0 крэшей
- Холодное извлечение ~7–9 c (включая bootstrap player.js),
  повтор из кэша — миллисекунды
- На том же устройстве/IP yt-dlp: ~11.8 c холодный CLI

## Ограничения (честно)

- Репутация IP — потолок для любого экстрактора; датацентр/VPN
  YouTube режет всем одинаково
- YouTube меняет поверхность каждые пару недель; в KMEP это обычно
  правка конфига, но не всегда
- Pre-1.0: API двигался между 0.2 и 0.3, ещё подвигается до 1.0
