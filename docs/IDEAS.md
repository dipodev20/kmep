# Идеи сверх исходной спецификации

## 1. Не хардкодить nsig/cipher-алгоритмы — выполнять весь player.js

Изначально планировалось вычленять функцию расшифровки regex'ом и
выполнять только её. Не сработало: актуальный player.js обфусцирует
строковые литералы через таблицу с XOR-обфусцированными индексами —
вырезанная функция без остального файла не может разрешить зависимости.

Текущий подход: `StreamResolver` выполняет ВЕСЬ `player.js` в JS-движке
через browser-shim (заглушки под window/document/navigator), один раз на
файл, дальше вызывает уже готовую публичную функцию на `_yt_player` без
повторной загрузки. Подтверждение извне: сам yt-dlp перешёл на такой же
подход (см. их пакет yt-dlp-ejs, требующий deno/node/QuickJS).

## 2. Orchestrator не останавливается на первом успешном клиенте

Порог `targetMinHeight` в `RemoteConfig`: если первый успешный клиент
отдал только 360p, Orchestrator пробует следующего клиента, пока не
достигнет порога или не кончится список.

## 3. Backend как "рубеж последней надежды"

Backend использует yt-dlp целиком, не дублирует свою крипто-логику.
Не проксирует видео-трафик — отдаёт клиенту прямые URL.

## 4. CacheManager как интерфейс, а не сразу Hive

Развязывает тестирование ядра от платформенной части.

## 5. Коды ошибок как enum

`KMEPErrorCode` enum вместо строк — компилятор заставляет явно
обработать любую новую ошибку.

## Статус диагностики n-sig entry point (актуально на момент восстановления)

См. `docs/AGENT_HANDOFF.md` — там подробный лог того, что уже
попробовано, что сработало (WEB-клиент с signatureTimestamp, патч
`window=this`), что нет (regex-извлечение функции, кандидат `eAO` —
ложное срабатывание).
